1. 执行摘要

NVIDIA LocateAnything 是一个面向自然语言视觉定位的 VLM 系统。Hugging Face Space 只是在线 demo；真正可复用的核心在 nvidia/LocateAnything-3B 模型仓库及其 batch_infer.py、batch_utils、kernel_utils 推理工具。

本地部署可行 推荐 Linux/WSL2 + NVIDIA GPU + CUDA + PyTorch，使用 uv 管理 Python 环境。
推荐用途 作为训练期 VLM teacher 或伪标签源，为 YOLO 学生模型生成开放词表候选框。
部署边界 当前项目默认部署期保持 YOLO-only；LocateAnything 不应进入学生模型在线推理链路。
首选路线：不要复刻 Space UI 作为生产工具。应直接使用模型仓库的批量推理入口，生成 JSONL 结果，再转换成 YOLO/COCO 伪标签，最后纳入配置驱动实验。
决策摘要
问题 判断 原因
能否本地部署 可以 模型仓库包含 Transformers remote code、模型配置、批量推理脚本和可选高吞吐推理工具。
是否适合当前项目 适合作为训练期 teacher 候选 支持开放词表检测、短语 grounding、OCR、GUI grounding、pointing；对低标签数据扩展有价值。
是否替代 Grounding DINO / YOLO-World 不建议直接替代 应先作为第三路伪标签源做质量评估，与现有 teacher 交叉过滤。
是否直接信任输出框 不建议 输出主要是结构化文本坐标，没有传统 detector confidence；需要外部质量过滤。
是否适合航拍小目标 值得实验但需谨慎 模型卡覆盖 aerial imagery 评估，但 Space 默认短边 cap 1024，可能损失 VisDrone 小目标。

3. Space 仓库拆解

Space 仓库非常薄，主要是 demo 包装层，不是训练或评测工程。它适合学习 API 形状、prompt 模板、结果解析和可视化方式，但不适合作为当前项目的直接工程依赖。

Space 文件结构
文件/目录 作用 复用价值
README.md Space metadata、标题、论文链接。 低；信息很短。
app.py 模型加载、图片/视频推理、输出解析、绘制结果、Gradio API。 中；可参考 prompt、坐标解析和 demo API。
index.html 自定义前端，调用 /run_inference API。 低；当前项目不需要 UI。
requirements.txt Space 运行依赖。 中；可作为最小环境参考。
assets/ 示例图片与字体。 低；仅 demo 用。

Space 中的核心类与函数

  • EagleWorker：封装 AutoTokenizer、AutoProcessor、AutoModel，使用 trust_remote_code=True 加载模型。
  • generate_raw_prompt：根据任务类型生成 prompt，支持 Detection、Grounding、OCR、GUI、Pointing。
  • parse_mixed_results：解析模型输出中的 <ref> 与 <box> 标签。
  • draw_on_frame：把归一化框或点画回原图/视频帧。
  • run_image_gpu_api / run_video_gpu_api：ZeroGPU 包装的图片与视频推理入口。
  • run_inference_api：Gradio 暴露的队列 API，前端调用这个接口。

Space UI 暴露的任务和参数

参数 可选值/默认值 说明
task_type Detection / Grounding / OCR / GUI / Pointing 决定 prompt 模板。
model_mode hybrid / fast / slow 决定生成模式；OCR demo 默认切到 slow。
short_size 空值时自动 cap 到 1024 输入短边缩放上限；航拍小目标应重点调参。
temp / top_p / top_k 0.7 / 0.9 / 20 采样参数；伪标签生成建议先固定并降低随机性。
max_video_frames 默认 4，UI 最大 10 视频 demo 是抽帧检测，不是时序跟踪。
隐私注意：Space 源码包含可选日志逻辑，只有设置 LOG_HF_TOKEN 时才会通过 CommitScheduler 写入指定 dataset；但使用公共 Space 上传数据时，仍不应上传敏感图片、未授权数据集或内部业务素材。

4. 模型能力与推理机制

LocateAnything-3B 是一个通用视觉语言定位模型，目标是把自然语言描述转成结构化框或点。模型卡将其定位为研究开发用途，覆盖开放词表检测、dense detection、referring expression grounding、文档/OCR、GUI grounding、机器人/自动驾驶和遥感等场景。

架构组成

  • 语言模型：Qwen2.5-3B-Instruct。
  • 视觉编码器：MoonViT-SO-400M。
  • 多模态连接：MLP projector。
  • 模型仓库使用 Transformers AutoModel remote code。

核心机制

  • Parallel Box Decoding，将 box/point 作为结构化块预测。
  • 支持 fast、slow、hybrid 三种模式。
  • 输出文本中嵌入 <box> 坐标 token。
  • 坐标归一化到 [0,1000]。

支持任务与 prompt 模板

任务 输出 推荐 prompt 模板
Object Detection 多框 Locate all the instances that matches the following description: car</c>person.
Phrase Grounding 单框或多框 Locate all the instances that match the following description: people wearing red shirts.
Scene Text Detection 文本区域框 Detect all the text in box format.
GUI Grounding 区域框或点 Locate the region that matches the following description: search button.
Pointing 点 Point to: traffic light.

输出格式

模型输出是文本，不是 detector 常见的张量数组。典型输出如下：

<ref>car</ref><box><128><532><214><612></box>
<ref>person</ref><box><404><461><432><548></box>

解析时需要将归一化坐标映射回像素坐标：

x1_px = x1 / 1000 * image_width
y1_px = y1 / 1000 * image_height
x2_px = x2 / 1000 * image_width
y2_px = y2 / 1000 * image_height
对 YOLO 伪标签的含义：转换到 YOLO label 时还要再变成 class_id x_center_norm y_center_norm width_norm height_norm。模型本身不会给出 YOLO 所需的类别 id，需要外部类别词表映射。

模型仓库中的批处理能力

模型仓库包含 batch_infer.py，每条请求只需要图片路径与 query 字符串，输出 JSONL 包含原始响应和 stats。这比调用 Space API 更适合离线伪标签生产。

模型仓库关键文件
文件/目录 作用
batch_infer.py 批量推理 CLI，支持 --requests JSONL、--batch-size、--attn、--scheduler、--out。
batch_utils/ 批量 hybrid generation runtime，处理模型加载、tokenization、图像特征缓存、调度。
kernel_utils/ LA Flash sparse range attention 工具，用于高吞吐推理路径。
processing_locateanything.py 处理图片、视频、chat template 和视觉输入。
modeling_locateanything.py Transformers 模型 remote code。
generate_utils.py box/point 生成、合法性检查和解码逻辑。

5. 本地部署方案

推荐把本地部署分成两个层级：先跑通批量推理，再根据需要复刻 Space UI。对于当前 YOLO 蒸馏项目，第一层级已经足够。

5.1 环境建议

项目 建议 备注
操作系统 Linux 或 WSL2 Ubuntu 模型卡主要支持 Linux。Windows 原生 CUDA/PyTorch 可能能跑，但不作为首选。
GPU NVIDIA GPU，建议 16GB 显存起步，24GB+ 更稳 高分辨率图片、batch 推理、long prompt 都会抬高显存。
Python 3.10 Space 使用 3.10.13。
包管理 uv 符合当前仓库规则。
PyTorch 按 CUDA 版本安装 CUDA wheel 不要盲装 CPU 版 torch。
Hugging Face 可选 HF_TOKEN 公开模型通常可直接下载；受限网络或许可门控时需要登录。

5.2 推荐部署：模型仓库批量推理

这是本项目最应该优先验证的路径。

git clone https://huggingface.co/nvidia/LocateAnything-3B
cd LocateAnything-3B

uv venv --python 3.10
source .venv/bin/activate

# 根据本机 CUDA 版本调整 index-url。下面以 CUDA 12.8 wheel 为例。
uv pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128

uv pip install \
  opencv-python-headless==4.11.0.86 \
  transformers==4.57.1 \
  numpy==1.25.0 \
  Pillow==11.1.0 \
  peft \
  decord==0.6.0 \
  lmdb==1.7.5 \
  huggingface_hub

准备请求文件：

# requests.jsonl
{"image":"/data/visdrone/images/000001.jpg","query":"pedestrian</c>people</c>bicycle</c>car</c>van</c>truck</c>tricycle</c>awning-tricycle</c>bus</c>motor"}

先用保守配置做 smoke test：

python batch_infer.py \
  --model nvidia/LocateAnything-3B \
  --requests requests.jsonl \
  --batch-size 1 \
  --attn sdpa \
  --scheduler eager \
  --max-new-tokens 2048 \
  --temperature 0.1 \
  --top-p 0.9 \
  --out locateanything_outputs.jsonl

确认输出正常后，再尝试提高 batch 或切换 attention 后端：

# 高吞吐尝试路径，需 flash-attn 等依赖可用
python batch_infer.py \
  --model nvidia/LocateAnything-3B \
  --requests requests.jsonl \
  --batch-size 4 \
  --attn la_flash \
  --scheduler pipeline \
  --out locateanything_outputs.jsonl
注意：la_flash、magi 属于性能路径，不是首个 smoke test 的必要条件。第一次部署应先用 sdpa 跑通功能，再优化吞吐和显存。

5.3 可选部署：复刻 Space UI

如果需要给人工验收或可视化标注检查使用，可以复刻 Space demo。它不是伪标签生产的首选路径。

git clone https://huggingface.co/spaces/nvidia/LocateAnything
cd LocateAnything

uv venv --python 3.10
source .venv/bin/activate

uv pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
uv pip install -r requirements.txt

export MODEL_PATH=nvidia/LocateAnything-3B
python app.py

浏览器打开 Gradio 提示的本地地址即可。Space UI 适合小批量观察输出，但不适合跑完整 VisDrone 数据集。

5.4 不优先推荐：直接走在线 Space API

在线 Space API 可用于少量交互测试，但不推荐用于数据集级伪标签生成：

  • ZeroGPU 队列和时长限制会影响吞吐。
  • 公共服务上传数据存在隐私和许可风险。
  • API 的输出侧重 demo 可视化，不如本地 JSONL 批处理稳定。
  • 无法严格固定依赖、模型版本和日志策略。

5.5 vLLM / SGLang 路径判断

模型卡列出 vLLM 和 SGLang 的 OpenAI-compatible serve 示例，但当前项目不应把它作为第一部署方案。原因是：伪标签生产需要完整保留 LocateAnything 的 grounding prompt、box token 输出、hybrid/fast/slow 生成模式和解析流程；官方 batch_infer.py 更直接、更可审计。

结论：先用 Transformers + batch_infer.py。只有当批量推理成为瓶颈，并且已完成输出一致性验证后，再考虑 vLLM/SGLang 或 LA Flash 优化。

6. 批量伪标签生产方案

针对当前仓库的 VFM-assisted YOLO distillation 目标，LocateAnything 最合适的集成方式是离线伪标签源。整个流程应配置驱动，输出产物不提交 Git。

6.1 推荐流水线

  1. 从数据集 YAML 或图片目录生成 image manifest。
  2. 把 VisDrone 类别词表拼成 LocateAnything query。
  3. 运行 batch_infer.py 输出 JSONL。
  4. 解析 raw_response 中的 <ref> 和 <box>。
  5. 映射类别名到 VisDrone class id，过滤非法框、过小框、异常长宽比框。
  6. 与 Grounding DINO / YOLO-World / 已有 YOLO baseline 交叉过滤。
  7. 导出 YOLO 标签目录或 COCO JSON，并写入新的 dataset config。
  8. 跑小样本 QA：可视化 50-200 张图，统计每类框数、面积分布和重复框。

6.2 Query 设计

VisDrone 类别可直接使用英文类名，但需要对可能歧义的类别做 prompt 约束。

VisDrone 类别 LocateAnything query 建议 备注
pedestrian / people pedestrian</c>people 两者语义接近，需在后处理或人工 QA 中检查混淆。
bicycle / motor bicycle</c>motorcycle VisDrone 的 motor 建议转成更自然的 motorcycle 查询词。
car / van / truck / bus car</c>van</c>truck</c>bus 适合作为第一批质量验证类别。
tricycle / awning-tricycle tricycle</c>awning tricycle 长尾类别，预期混淆较高，需要单类评估。

推荐第一轮用全类别 query 跑小样本，再比较单类 query 是否提高定位质量：

# 全类别 query
pedestrian</c>people</c>bicycle</c>car</c>van</c>truck</c>tricycle</c>awning tricycle</c>bus</c>motorcycle

# 单类 query 示例
car
pedestrian
small vehicles in aerial image

6.3 输出解析策略

解析器需要兼容三种常见情况：

  • <ref>label</ref><box><x1><y1><x2><y2></box>：标准框。
  • <box><x><y></box>：点输出，通常来自 pointing，不应直接转成检测框。
  • 自然语言夹杂结构化标签：需要用正则抽取标签和坐标，不能依赖整段文本格式完全稳定。
def normalized_box_to_yolo(coords, image_w, image_h):
    x1, y1, x2, y2 = coords
    x1 = max(0.0, min(1.0, x1 / 1000.0))
    y1 = max(0.0, min(1.0, y1 / 1000.0))
    x2 = max(0.0, min(1.0, x2 / 1000.0))
    y2 = max(0.0, min(1.0, y2 / 1000.0))
    if x2 <= x1 or y2 <= y1:
        return None
    cx = (x1 + x2) / 2.0
    cy = (y1 + y2) / 2.0
    bw = x2 - x1
    bh = y2 - y1
    return cx, cy, bw, bh

6.4 过滤与融合建议

过滤层 规则 目的
格式过滤 坐标数量必须为 4；x2 > x1、y2 > y1；归一化后必须在图像内。 去除解析错误和退化框。
尺寸过滤 设置最小宽高、最小面积、最大面积占比。 减少大范围 hallucination 框和极小噪声框。
类别过滤 只保留 VisDrone 类别词表可映射标签。 避免自由文本 label 污染训练集。
一致性过滤 与 Grounding DINO、YOLO-World、YOLO baseline 的框做 IoU 或中心点一致性检查。 弥补 LocateAnything 没有传统 confidence 的问题。
重复框融合 同类框 NMS / WBF，类别冲突时保留教师共识更高的类别。 减少重复标签和冲突标签。

7. 与当前 VFM-YOLO 蒸馏项目的集成建议

当前仓库的规则是：DINOv3、Grounding DINO、YOLO-World 默认作为训练期 teacher 或伪标签源；部署期学生模型保持 YOLO-only，除非明确做 teacher-in-the-loop 推理实验。LocateAnything 应遵循同样边界。

推荐落点

模块 建议 说明
configs/teachers/ 新增 LocateAnything teacher 配置 记录模型 id、推理模式、类别映射、过滤阈值。
scripts/ 新增小型可复现脚本 只做 manifest 生成、批量调用、格式转换；复杂逻辑下沉到 src/。
src/vfm_yolo_distillation/ 新增可复用解析和伪标签转换逻辑 如 locateanything_parser.py、pseudo_label_fusion.py。
configs/experiments/ 新增对照实验配置 例如 quality mix、teacher agreement、single-teacher ablation。
runs/ 或外部目录 存放生成伪标签和中间 JSONL 不要提交数据集、权重、推理产物。

第一阶段实验设计

  1. 小样本可行性：随机抽取 100-300 张 VisDrone train 图片，运行全类别 query。
  2. 视觉 QA：生成带框可视化，按类别检查漏检、错检、框偏移、重复框。
  3. 统计 QA：比较每类框数、面积分布、宽高比分布与 GT / Grounding DINO / YOLO-World。
  4. 一致性实验：分别测试 LocateAnything 单源、LocateAnything + Grounding DINO 共识、LocateAnything + YOLO-World 共识。
  5. 短训验证：只在 10% 标签设定跑短程 pseudo-label training，先看是否出现明显负迁移。

与已有 teacher 的角色划分

Teacher 优势 限制 建议角色
DINOv3 强通用视觉表征，可做 objectness / feature distillation。 不直接输出类别框；全图 patch 对小目标容易稀释。 特征蒸馏、objectness 辅助、候选区域信号。
Grounding DINO 开放词表检测成熟，输出框和 score。 类别 prompt 与阈值敏感；小目标质量需校准。 主力伪标签 teacher 之一。
YOLO-World YOLO 风格检测速度快，输出更接近学生训练格式。 开放词表质量受类别词和分布影响。 伪标签候选与 detector agreement。
LocateAnything VLM grounding 能力强，覆盖 dense detection、OCR、短语 grounding、遥感评估。 输出是文本坐标，没有标准 confidence；本地显存需求高。 第三路开放词表 teacher，用于补充和交叉验证。
建议优先级：先做 LocateAnything 小样本伪标签质量审计，再决定是否写完整训练脚本。不要一开始就跑全量数据集，避免生成大量难以审计的噪声标签。

风险 表现 规避策略
显存不足 加载失败、OOM、batch 推理不稳定。 先用 batch-size=1、sdpa、较低分辨率 smoke test；再逐步扩大。
小目标缩放损失 Space 默认短边 cap 1024，航拍小目标可能被压得过小。 本地批量推理评估不同输入尺寸或切图策略；不要直接沿用 Space 默认。
无 detector confidence 难以按置信度过滤伪标签。 使用 teacher agreement、NMS/WBF、面积分布、类别白名单和人工抽检替代。
文本输出不稳定 自然语言夹杂框标签，解析失败或 label 不规范。 写健壮 parser，保留 raw response，失败样本进入 QA 日志。
类别混淆 people/pedestrian、motor/bicycle、三轮车类别混淆。 做类别映射表，必要时拆成单类 query，按类统计伪标签质量。
trust_remote_code 执行模型仓库 Python 代码。 固定 commit/hash，审计 remote code，在隔离环境运行。
公共 Space 隐私 上传数据受服务端环境和日志策略影响。 敏感或内部数据只在本地运行，不走公共 Space。
训练负迁移 噪声伪标签拉低 YOLO 学生性能。 先跑短程 ablation；保持干净 baseline；不要用伪标签覆盖真标签。

部署期边界

LocateAnything 不应进入默认部署期推理链路。当前项目规则要求 deployment-time student models YOLO-only，除非实验明确研究 teacher-in-the-loop inference。LocateAnything 的合理位置是训练前/训练中生成伪标签或辅助分析，而不是线上检测器。

9. 本地部署验收清单

环境验收

  • nvidia-smi 可见目标 GPU，驱动与 CUDA 版本匹配。
  • python -c "import torch; print(torch.cuda.is_available())" 返回 True。
  • transformers==4.57.1、torch、torchvision、Pillow、opencv-python-headless 可正常导入。
  • 首次运行能完整下载模型文件，HF cache 不写入项目仓库。

功能验收

  • 单张图片推理输出 JSONL，并包含 raw_response。
  • raw_response 中能解析出至少一个合法 <box>。
  • 坐标映射回像素后没有负宽高、越界严重或整图框泛滥。
  • 同一张图片用固定参数重复运行，输出波动在可接受范围内。
  • 可视化结果和原图对齐，没有宽高交换、坐标顺序错误。

伪标签验收

  • 每类伪标签数量与 GT 分布或已有 teacher 分布没有数量级异常。
  • 小目标框面积分布合理，不被大量 1-2 像素框污染。
  • 抽检图像覆盖白天/夜晚、密集道路、稀疏场景、不同高度视角。
  • 伪标签输出目录、可视化目录和模型下载缓存均未被 Git 跟踪。
  • 短训实验必须保留 baseline、single-teacher、teacher-agreement 对照。

建议的最小实验矩阵

实验 样本 目的 通过条件
Smoke 10 10 张图片 确认环境、下载、推理、解析。 无崩溃，能解析合法框。
QA 100 100 张图片 人工看框质量和类别混淆。 主要类别框可用，没有系统性坐标错误。
Stats 300 300 张图片 统计分布、与 GT/其他 teacher 比较。 框数、面积、类别分布无明显异常。
Short train 10% 标签 + 伪标签 评估是否负迁移。 短程验证不明显低于 baseline。
